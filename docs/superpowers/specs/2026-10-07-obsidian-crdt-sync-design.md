# Obsidian CRDT 실시간 동기화 플러그인 — 설계 (1단계)

- 작성일: 2026-10-07
- 상태: 승인됨 (2026-10-07), 구현 계획 작성 중 보정 반영
- 범위: 1단계 (개인 다기기 동기화). 공개 배포(C)는 확장 가능하도록 구조만 열어둔다.

---

## 1. Problem 1-Pager

**Context**
- 사용자는 Obsidian 볼트를 git(Obsidian Git 플러그인)으로 기기 간 동기화하고 있다.
- 모바일(iOS/Android)에서는 git 사용이 어려워 사실상 편집/동기화가 막혀 있다.
- 사용자는 Oracle Free Tier VM을 보유하고 있다.

**Problem**
- 파일 단위 동기화(git)는 동시 편집 시 충돌이 나고, 실시간 반영이 되지 않는다.
- 모바일에서 수정한 내용을 git 기록으로 남길 경로가 없다.

**Goal**
- 데스크톱/모바일 Obsidian 간에 노션처럼 **충돌 없이 실시간으로** `.md` 노트를 함께 편집한다.
- 모바일 수정 → 서버 보관 → 데스크톱이 켜지면 디스크 반영 → 데스크톱에서 git 커밋, 이 흐름을 지원한다.

**Non-Goals (1단계)**
- 첨부파일(이미지/PDF 등 바이너리) 동기화
- 다중 사용자 계정, 공유 권한 UI, 공개 배포
- 종단간 암호화(E2EE)
- 서버 측 git 커밋
- `.obsidian/` 설정 폴더 동기화

**Constraints**
- 플러그인은 데스크톱과 모바일 모두에서 동작해야 한다 → Node 전용 API(`fs`, `net` 등) 사용 금지. Obsidian API와 브라우저 API만 사용한다.
- 서버는 사용자의 Oracle VM에서 운영한다. 무료 범위 내에서 운영 가능해야 한다.
- AGENTS.md 규칙: 파일 ≤ 300 LOC, 함수 ≤ 50 LOC, 부수효과는 경계로 분리, 비밀값을 코드/로그에 남기지 않는다.

## 2. 주요 결정과 비교

| # | 결정 | 고려한 선택지 | 선택 이유 |
|---|---|---|---|
| D1 | CRDT 라이브러리: **Yjs** + `y-codemirror.next` | Automerge | Obsidian 편집기(CodeMirror 6)용 바인딩이 성숙했고, 원격 커서와 협업 undo를 기본 제공한다. Automerge는 CM6 바인딩과 실시간 provider 생태계가 약하다. |
| D2 | 문서 분할: **파일마다 Y.Doc + 볼트 인덱스 Y.Doc 하나** | 볼트 전체를 Y.Doc 하나로 / 편집기 바인딩 없이 파일 diff 동기화만 | 볼트 크기와 무관하게 모바일 메모리 사용이 일정하고, 문서 단위 권한으로 확장하기 쉽다. Y.Doc 하나 방식은 볼트가 커질수록 무거워진다. diff 동기화만으로는 실시간 편집과 원격 커서가 안 된다. |
| D3 | 서버: **Oracle VM의 Hocuspocus(Node) + SQLite**, 클라이언트는 표준 Yjs 동기화 프로토콜만 사용 | Cloudflare Durable Objects / P2P(y-webrtc) | 이미 보유한 서버라 디버깅이 쉽다. 프로토콜이 표준이라 Cloudflare 백엔드는 나중에 추가할 수 있다. P2P는 기기들이 동시에 켜져 있어야 하고 모바일에서 불안정하다. |
| D4 | git과의 관계: **원본은 CRDT 하나. git 커밋/push는 "커밋 기기" 한 대만 하고, 다른 기기는 git pull을 하지 않는다** | git pull 유지 + 동기화 후 diff / git 충돌을 CRDT로 해결 | git pull로 들어온 변경은 기기마다 각자 "새 편집"으로 반영되어 텍스트가 중복 삽입된다. 이는 git 충돌이 없을 때도 생기므로 충돌 해결 로직으로는 막을 수 없다. 또 pull 내용은 CRDT보다 오래된 스냅샷이라 최신 편집을 되돌릴 위험도 있다. |
| D5 | fileId 저장: **인덱스 문서에만** (frontmatter 사용 안 함) | frontmatter에 `id:` 기록 | 노트 본문과 git diff에 노이즈를 만들지 않는다. |
| D6 | 디스크 바깥 변경 반영: **3-way (base 기준)** | 디스크와 Y.Text를 단순 diff | 단순 diff는 꺼져 있던 기기가 켜질 때 원격 수정을 되돌린다(§4.3). |
| D7 | E2EE: **1단계 미적용** (본인 서버를 신뢰) | E2EE | E2EE를 쓰면 서버가 업데이트를 병합/압축할 수 없고, 키 관리가 필요해 복잡도가 크게 는다. C 단계에서 재검토한다. |

## 3. 구성 요소

### 3.1 저장소 구조 (pnpm 모노레포, TypeScript)

```
obsidian-crdt/
  packages/shared/   # 문서 이름 규칙, 인덱스 스키마 타입, 검증 함수
  packages/plugin/   # Obsidian 플러그인 (esbuild 번들)
  packages/server/   # Hocuspocus 서버 + 토큰 CLI
  deploy/            # docker-compose.yml, Caddyfile
```

### 3.2 플러그인 모듈

핵심 로직은 Obsidian API를 직접 부르지 않고 **Port 인터페이스**를 통해서만 바깥과 통신한다. Obsidian 구현은 얇은 어댑터(`adapters/`)에 둔다.

| 모듈 | 책임 | 의존 |
|---|---|---|
| `SyncConnection` | Hocuspocus 서버와 WebSocket 연결 하나를 관리하고 여러 문서를 함께 주고받는다(multiplexing). 인증, 지수 백오프 재접속, 온라인 상태를 맡고, 상태 표시줄에 연결 상태를 보여준다. | `@hocuspocus/provider` |
| `VaultIndex` | 인덱스 Y.Doc 관리. `fileId ↔ path` 조회, 생성/이름 변경/삭제 표시, 같은 경로 충돌 해소. | `shared` |
| `DocManager` | 파일별 Y.Doc의 불러오기, IndexedDB 영속화, 백그라운드 동기화 큐(동시 개수 제한). 1단계는 모든 문서를 구독 상태로 유지한다(원격 변경을 받으려면 구독이 필요). 문서 내리기는 §9 측정 후 결정한다. | `y-indexeddb`, `StoragePort` |
| `EditorBinding` | 열린 Markdown 편집기(CM6)에 `yCollab`을 연결하고, 탭이나 파일이 바뀌면 다시 연결한다. 원격 커서를 표시한다. | `y-codemirror.next`, `EditorPort` |
| `DiskReconciler` | 디스크와 Y.Doc을 맞춘다. 자기가 쓴 변경 판별, 3-way 반영, 시작 시 전체 스캔, 대량 삭제 감지. | `VaultPort`, `diff-match-patch` |
| `Settings` | 서버 URL, 토큰, vaultId, 제외 경로 패턴, 커밋 기기 안내. | Obsidian 설정 UI |

**Port 인터페이스**
- `VaultPort`: `list()`, `read(path)`, `write(path, text)`, `create`, `rename`, `trash`, 이벤트 구독(`create/modify/delete/rename`)
- `EditorPort`: 열린 Markdown 편집기 목록과 각 편집기의 파일 경로, CM6 확장 등록
- `StoragePort`: 파일별 로컬 기록(`path`, `base`)과 부트스트랩 완료 플래그 저장

### 3.3 서버

- `@hocuspocus/server` + `@hocuspocus/extension-database` + Node 내장 `node:sqlite`로 Y.Doc 상태를 영속화한다. (`extension-sqlite`가 의존하는 better-sqlite3는 네이티브 빌드가 필요하고 npm 11에서 설치 스크립트가 기본 차단되므로 쓰지 않는다.)
- `onAuthenticate`: 토큰 해시를 비교해 vaultId를 확인하고, 문서 이름을 검증한다(§6).
- 토큰 CLI: `token create --vault <id>`, `token revoke <tokenId>`, `token list`. 원본 토큰은 생성 시 한 번만 출력하고 서버에는 SHA-256 해시만 저장한다(256비트 무작위 값이라 느린 해시가 필요 없다).
- 배포: Docker Compose(Hocuspocus + Caddy). Hocuspocus는 `127.0.0.1`에서만 대기하고, Caddy가 TLS를 종단한다. 외부 포트는 80/443만 연다.

### 3.4 데이터 모델

**문서 이름**
- 인덱스: `<vaultId>/index`
- 파일: `<vaultId>/<fileId>` (fileId는 UUID v4)
- 허용 정규식: `^[a-z0-9-]{8,64}/(index|[0-9a-f-]{36})$`

**인덱스 Y.Doc**
```
files: Y.Map<fileId, Y.Map{
  path: string          // 볼트 기준 상대 경로, NFC 정규화, '/' 구분자
  deleted: boolean
  createdAt: number     // UTC epoch ms
}>
```
- 항목마다 필드 단위 Y.Map을 써서, 이름 변경과 삭제가 동시에 일어나도 서로 덮어쓰지 않는다.

**파일 Y.Doc**
- `content: Y.Text` — 노트 전체 텍스트(frontmatter 포함)

**로컬 메타데이터 (StoragePort, IndexedDB)**
- `record[fileId] = { path, base }`: 이 기기 디스크에서 그 파일이 있는 경로와, 마지막으로 디스크와 맞췄던 텍스트
- 자기가 쓴 변경 판별은 별도 해시 없이 §4.3의 3-way 판단으로 처리한다. 플러그인이 X를 쓰면 `base = X`이므로, 그 쓰기로 생긴 `modify` 이벤트는 "디스크 == 현재" 또는 "디스크 == base"로 판정된다.

## 4. 데이터 흐름

### 4.1 열린 편집기에서 타이핑
1. CM6 변경 → `yCollab` → Y.Text → IndexedDB 저장 + 서버 전송
2. 다른 기기의 Y.Doc → 그 기기에서 열린 편집기에 즉시 반영
3. 디스크 저장은 Obsidian 자동저장이 맡는다.
4. **바인딩된 편집기가 열린 파일의 `modify` 이벤트는 DiskReconciler가 무시한다.** 이때는 편집기가 원본이다. 바깥 도구가 그 파일을 바꾸면 Obsidian이 편집기 내용을 다시 불러오고, 그 변경이 CM6 → yCollab 경로로 Y.Text에 들어간다.
   - 이유: 타이핑 중에 저장이 일어나면 디스크 내용이 Y.Text보다 한 박자 늦다. 이걸 "바깥 변경"으로 오해하면 입력이 중복 삽입된다.

### 4.2 원격 변경 — 파일이 열려 있지 않을 때
1. Y.Doc 업데이트 → `DISK_WRITE_DEBOUNCE_MS`(1000ms) 디바운스
2. §4.3의 판단을 실행한다. 디스크가 바깥에서 바뀌지 않았다면 `ytext.toString()`을 쓰고 `base`를 갱신한다.
3. 이 쓰기로 생기는 `modify` 이벤트는 §4.3에서 "디스크 == 현재"로 판정되어 아무 일도 하지 않는다.

### 4.3 디스크가 바깥에서 바뀜 — 3-way 반영
열려 있지 않은 파일의 `modify` 이벤트를 받았을 때와, 앱을 켤 때 전체 스캔에서 같은 절차를 쓴다.

```
disk = 디스크 내용, base = 마지막으로 맞췄던 내용, current = 현재 Y.Text

if disk == current:            base = disk; 끝
elif base 없음:                 부트스트랩 (§4.5) — 현재(서버) 내용을 유지하고, 디스크 내용은 conflict 사본으로 저장
elif disk == base:             디스크가 바깥에서 바뀌지 않음 → current를 디스크에 쓴다 (§4.2)
else:                          디스크가 실제로 바뀜
    patches = dmp.patch_make(base, disk)
    merged  = dmp.patch_apply(patches, current)
    applyMinimalDiff(Y.Text, current → merged)   // origin: "disk"
    disk에 merged를 쓰고 base = merged
```
- **핵심 시나리오:** 모바일에서 수정 → 서버 보관 → 데스크톱 Obsidian 실행 → 서버와 동기화 → 스캔에서 `disk == base`이므로 Y.Text(모바일 수정 포함)를 디스크에 쓴다 → 커밋 기기가 git 커밋.
- Y.Text 반영은 **code point 단위 diff**로 한다. UTF-16 단위 diff는 이모지의 서로게이트 쌍을 쪼개고, Yjs가 이를 인코딩할 때 `U+FFFD`로 깨진다(실측으로 확인).
- 병합 결과에 짝 없는 서로게이트가 있으면 병합 실패로 본다.
- 일부 patch가 적용되지 않으면(`patch_apply`의 결과가 false) 해당 파일을 `이름 (conflict-disk YYYY-MM-DD <fileId 앞 6자>).md`로 저장하고 알림을 띄운다. 디스크 쪽 변경을 버리지 않기 위해서다.
- 시작 스캔은 **서버와 처음 동기화가 끝난 뒤에** 실행한다. 오프라인이면 로컬 IndexedDB 상태를 기준으로 실행하고, 재접속하면 CRDT가 병합한다.

### 4.4 생성 / 이름 변경 / 삭제
- **생성(로컬):** UUID를 만들고 인덱스에 `{path, deleted:false, createdAt}`를 등록한 뒤, 디스크 내용으로 Y.Text를 초기화한다.
- **생성(원격):** 인덱스에 새 항목이 생기면 해당 문서를 동기화한 뒤 디스크에 파일을 만든다.
- **이름 변경:** 로컬 rename 이벤트 → 인덱스의 `path`를 갱신한다. 원격 변경이 오면 `VaultPort.rename`을 호출한다. 동시에 바꾸면 Y.Map 규칙에 따라 한 값으로 수렴한다.
- **삭제:** `deleted = true`로 표시한다. 원격 삭제는 `VaultPort.trash`(볼트 `.trash`로 이동)로 처리한다. 편집과 삭제가 동시에 일어나면 삭제가 이기지만 휴지통에 남는다.
- **git이 한 이름 변경**(삭제 + 생성으로 보임): 같은 디바운스 구간 안에서 삭제된 파일과 새 파일의 내용이 같으면, 같은 fileId의 이름 변경으로 처리한다.
- **같은 경로 충돌**(오프라인에서 각자 생성 등): 삭제 표시가 없는 항목 둘 이상이 같은 path를 가지면, fileId가 사전순으로 가장 작은 항목이 경로를 유지한다. 나머지는 `이름 (conflict YYYY-MM-DD <fileId 앞 6자>).md`로 옮긴다. 날짜는 `createdAt`의 **UTC 날짜**를 쓴다. 기기마다 시간대가 달라도 같은 이름이 계산되어야, 여러 기기가 동시에 처리해도 같은 값으로 수렴하기 때문이다.

### 4.5 새 기기 첫 연결 (부트스트랩)
기존 파일이 이미 있는 기기(예: git clone한 볼트)가 처음 연결할 때, 디스크 내용으로 Y.Doc을 따로 초기화하면 서버 내용과 합쳐져 텍스트가 두 배가 된다. 그래서 다음 절차를 따른다.
1. 첫 동기화는 **온라인 필수**다. 오프라인이면 "첫 동기화는 온라인에서 필요" 알림을 띄우고 대기한다.
2. 서버 인덱스를 먼저 받아서 경로 기준으로 로컬 파일과 fileId를 매칭한다.
3. 매칭된 파일: 서버 문서와 동기화가 **끝난 뒤에** §4.3을 수행한다(base 없음). 내용이 같으면 기록만 남긴다. 다르면 서버 내용이 이기고, 디스크 내용은 conflict 사본으로 남긴다. (처음 초안의 "base = 서버 텍스트"는 오래된 git clone 내용으로 서버의 최신 편집을 되돌리므로 폐기했다.)
4. 서버에 없는 파일만 §4.4의 로컬 생성으로 등록한다.
5. 서버 인덱스에만 있는 파일은 디스크에 만든다.

## 5. 오프라인, 재접속, 오류 처리

| 상황 | 동작 |
|---|---|
| 오프라인 편집 | Y.Doc과 IndexedDB에 쌓아둔다. 재접속하면 상태 벡터 교환으로 빠진 업데이트만 주고받는다. |
| 모바일이 백그라운드에서 돌아옴 | `visibilitychange` 이벤트에서 연결 상태를 확인하고 즉시 재접속한다. |
| 서버 연결 불가 | 상태 표시줄에 "오프라인"을 표시한다. 로컬 편집은 계속되고, 지수 백오프(최대 `RECONNECT_MAX_DELAY_MS` = 30s)로 재시도한다. |
| 인증 실패 | 알림을 띄우고 재시도를 멈춘다. 설정을 바꾸면 다시 시도한다. |
| IndexedDB 손상 / 열기 실패 | 로컬 캐시를 비우고 §4.5 부트스트랩을 다시 수행한다. |
| 대량 삭제 감지 (`MASS_DELETE_WINDOW_MS` = 10s 안에 `MASS_DELETE_THRESHOLD` = 10개 이상) | 동기화를 일시정지하고 확인 모달을 띄운다. 사용자가 확인하면 반영하고, 취소하면 서버 기준으로 복원한다. |
| `.md`가 `MAX_SYNC_FILE_BYTES`(2MB)를 넘음 | 동기화에서 제외하고 알림을 띄운다. |
| 동기화 제외 경로 | `.obsidian/`, `.trash/`, `.git/`, 그리고 `.md`가 아닌 모든 파일 |

- 예외는 구체적인 타입만 잡는다(연결 오류, 인증 오류, 저장소 오류). 사용자에게는 원인과 조치를 담은 메시지를 보여준다.

## 6. 보안

- **전송:** `wss://`만 허용한다. `ws://`는 호스트가 `localhost`/`127.0.0.1`일 때만 허용한다.
- **인증:** 볼트별 토큰(256비트 무작위 값). 서버에는 SHA-256 해시만 저장하고, 폐기를 지원한다.
- **권한:** 문서 이름을 §3.4 정규식으로 검증하고, 문서의 vaultId가 토큰의 vaultId와 같아야만 허용한다. 최소 권한 원칙을 따른다.
- **자원 제한:** 서버에 WebSocket 메시지 크기 상한(8MB)을 둔다. 토큰별 동시 연결 수 상한은 연결 하나로 여러 문서를 주고받는(multiplexing) 구조에서 측정 기준이 모호해서, 다중 사용자 단계(C)로 미룬다.
- **토큰 저장:** 대상 Obsidian 버전에 플러그인용 비밀 저장 API가 있으면 그것을 쓴다. 없으면 `data.json`에 저장하고, 설정 화면에 "`.obsidian`을 git에 커밋하면 토큰이 노출됨" 경고와 `.gitignore` 안내를 표시한다.
- **로그:** 구조화 로그(JSON)를 쓴다. 문서 내용과 토큰은 기록하지 않는다. 기록 항목은 연결 ID, 문서 이름, 이벤트 종류, 오류 코드다.

## 7. 테스트 전략

- **단위 (Vitest):** `applyMinimalDiff`(원격 문서로 왕복해도 이모지가 보존되는지 포함), 3-way 병합(§4.3), 인덱스 연산, conflict 이름 생성(UTC), 경로 필터, 문서 이름 검증, 대량 삭제 감지, 파일 크기 상한. 경계 사례로 빈 문자열, 한글/이모지(UTF-16 서로게이트), CRLF를 포함한다.
- **수렴 테스트:** 메모리 위의 가상 기기 N대가 시드를 고정한 무작위 편집, 무작위 동기화 순서, 오프라인 구간을 거쳐도 최종 텍스트와 인덱스가 같아야 한다.
- **회귀 테스트 (먼저 실패하게 작성):**
  1. 기존 파일이 있는 새 기기가 부트스트랩해도 텍스트가 두 배가 되지 않는다.
  2. 자기 자신이 쓴 `modify` 이벤트를 다시 반영하지 않는다.
  3. 바인딩된 편집기가 열린 파일의 저장 지연으로 입력이 중복되지 않는다.
  4. 꺼져 있던 기기가 다시 켜질 때 원격 수정이 되돌려지지 않는다.
  5. 오프라인에서 같은 경로를 각자 생성하면 conflict 사본이 정확히 하나만 생긴다.
- **통합:** 테스트 안에서 Hocuspocus를 임의 포트로 띄우고, `FakeVault`를 가진 플러그인 코어 두 개를 연결한다.
  - 정상: 편집, 생성, 이름 변경, 삭제가 상대편 가짜 디스크에 반영된다.
  - 실패: 잘못된 토큰은 거부되고 재시도하지 않는다. 다른 vaultId 접근은 거부된다. 연결이 끊긴 동안 편집하고 재접속하면 병합된다.
- **서버 단위:** 토큰 해시 검증, 폐기된 토큰 거부, 메시지 크기 상한.
- **수동 E2E 체크리스트:** 맥 두 창 / 맥과 아이폰 사이에서 동시 타이핑, 원격 커서, 백그라운드 복귀, 비행기 모드로 편집 후 복귀, 모바일 수정이 데스크톱 git 커밋까지 이어지는지.

## 8. 운영 가이드 (README에 반영)

- 플러그인을 쓰는 모든 기기에서 **Obsidian Git의 auto-pull을 끈다.**
- git 커밋/push는 **커밋 기기 한 대**에서만 한다. 다른 데스크톱은 git을 쓰지 않거나 읽기 전용으로 둔다.
- git 충돌이 생기면 **작업 트리(CRDT) 버전을 우선**한다.
- `.obsidian/plugins/<plugin-id>/data.json`을 `.gitignore`에 추가한다.

## 10. 추후 계획 (1단계 범위 밖)

- **첨부파일 동기화:** 바이너리는 CRDT로 병합할 수 없으므로 "마지막에 쓴 쪽이 이김" 방식의 블롭 저장소(내용 해시 주소)와 인덱스 연동이 필요하다.
- **서버 측 git 커밋:** 서버가 주기적으로 볼트를 내보내 커밋하고 push한다. 커밋 기기가 필요 없어진다.
- **Cloudflare Durable Objects 백엔드:** 같은 Yjs 프로토콜로 서버리스 운영을 지원한다.
- **공개 배포(C):** 사용자 계정, 폴더/문서 단위 공유와 권한, E2EE 재검토, 커뮤니티 플러그인 등록.

## 11. 가정 (Assumptions)

- A1. 사용자의 볼트에서 동기화 대상 `.md`는 수천 개 이하이고, 파일 하나는 대부분 2MB보다 작다.
- A2. 동시 편집 기기는 개인 기준 2~4대다.
- A3. Oracle VM에 Docker를 설치할 수 있고, 도메인(또는 DDNS)을 연결할 수 있다.
- A4. Obsidian 최소 지원 버전은 구현을 시작할 때 최신 안정 버전 기준으로 정하고 `manifest.json`에 명시한다.
