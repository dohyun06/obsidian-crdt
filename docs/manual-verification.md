# 실제 Obsidian 검증 목록

자동 테스트로 확인할 수 없는 항목입니다 (스펙 §9). 두 기기(또는 두 볼트 창)에 같은 서버, 같은 볼트 ID로 플러그인을 설치하고, 설정에서 **디버그 로그**를 켠 뒤 진행합니다.
각 항목에 결과(통과 / 실패 + 관찰 내용)를 적고, 실패하면 스펙 §9의 대안을 적용합니다.

> **주의:** 한 기기에서 두 볼트로 시험할 때, 두 볼트의 **폴더 이름과 볼트 ID가 모두 같으면** 로컬 상태(IndexedDB `crdt-sync/<폴더 이름>/<볼트 ID>`)를 함께 써서 결과가 틀어집니다. 볼트 ID나 폴더 이름 중 하나를 다르게 하세요. (다른 기기끼리는 같은 볼트 ID를 써야 서로 동기화됩니다.)

## 디버그 로그 읽는 법
설정의 **디버그 로그**를 켜면 개발자 콘솔(Cmd/Ctrl+Shift+I)에 `CRDT Sync <이벤트> {필드}` 형식으로 찍힙니다 (설정을 바꾸면 바로 적용). 필드에는 경로, fileId, 개수만 있고 노트 내용이나 토큰은 절대 없습니다.

| 이벤트 | 뜻 |
| --- | --- |
| `vault-event {kind, path, oldPath?}` | 엔진이 처리하는 볼트 이벤트 (create / modify / rename / delete) |
| `echo-consumed {kind, path}` | 플러그인 자신이 한 이름 변경·삭제의 메아리라서 무시함 |
| `open-doc {path, outcome}` | 편집기용 문서 요청 결과: `opened`, `untracked`(아직 추적 안 함), `not-reconciled`, `absorbed-<결정>`(바인딩 전 편집기 내용을 합친 결과: `in-sync` / `write-disk` / `merge` / `conflict`) |
| `editor-open {fileId, count}` / `editor-closed {fileId, stillOpen}` | 엔진이 fileId 기준으로 센 열린 편집기 수 |
| `bind-requested {path}` / `bind-attached {path, fileId}` | 편집기 바인딩 시작 / 완료 |
| `bind-retry {path, delayMs}` / `bind-given-up {path}` | 아직 추적되지 않아 재시도 / 그 편집기가 다른 파일로 가거나 닫혀서 중단 |
| `bind-editor-changed {path, request}` | 문서를 여는 동안 편집기 내용이 바뀌어 다시 요청함 |
| `guard-drop {path}` | 파일 전환 보호 장치가 바인딩을 끊음 (§9 CM6 재사용) |
| `release {path, save}` / `rebind {views}` | 바인딩 해제 / 이름 변경 등으로 모든 편집기 재평가 |

## 1. 편집기
- [ ] 두 기기에서 같은 노트를 열고 동시에 타이핑 → 양쪽 내용이 같고, 상대 커서와 기기 이름이 보인다.
- [ ] 한 노트를 연 상태에서 다른 노트로 전환(같은 탭) → 이전 노트 내용이 바뀌지 않는다. (§9 CM6 재사용 위험)
- [ ] 탭 하나에서 다른 노트로 전환할 때 Obsidian이 내용을 먼저 지우거나 바꾸고 나서 파일을 바꾸는지 기록한다 (디버그 로그: `guard-drop` → `release` → `bind-requested` → `bind-attached` 순서와 경로). 이전 노트 내용이 절대 바뀌지 않아야 한다. (§9 CM6 재사용 위험: 보호 장치는 파일 getter가 바뀐 뒤의 내용 변경만 막는다)
- [ ] 노트 이름을 파일 탐색기에서 바꾼 직후 바로 타이핑 → 첫 글자가 사라지지 않고 내용이 두 번 들어가지 않는다. (디버그 로그: `vault-event {kind: rename}` → `rebind` → 새 경로의 `bind-attached`, 그 사이 `editor-closed`의 `stillOpen`이 `true`)
- [ ] 플러그인을 끈 상태(또는 '다시 연결' 중)에 열린 노트에 타이핑하고 저장 전에 동기화를 켠다 → 입력한 글자가 사라지지 않는다. (디버그 로그: `open-doc`의 `outcome`이 `absorbed-merge` 또는 `absorbed-in-sync`)
- [ ] 노트를 연 상태에서 다른 프로그램으로 그 파일을 수정 → Obsidian이 편집기를 다시 불러올 때 다른 기기의 동시 편집이 사라지지 않는다. (§9 편집기 재로딩 위험)
- [ ] Cmd/Ctrl+Z가 내 입력만 되돌린다 (상대 입력은 남는다).
- [ ] 노트를 빠르게 타이핑하다 곧바로 탭을 닫는다 → 닫은 뒤 다른 기기에서 수정해도 텍스트가 두 번 들어가지 않는다. (닫기 순서)
- [ ] 같은 노트를 두 창에 열고 하나만 닫는다 → 남은 창에서 계속 실시간 동기화된다.

## 2. 파일 작업
- [ ] 새 노트를 만들고 바로 타이핑 → 다른 기기에 생기고 내용이 맞다.
- [ ] 연쇄 이름 변경 `a→b` 직후 `c→a`, 이름 맞바꾸기, 폴더 이동 → 두 기기의 경로와 내용이 같고 conflict 파일이 생기지 않는다. (§9 echo 위험; 받는 기기의 디버그 로그에서 자신의 이름 변경은 `vault-event`가 아니라 `echo-consumed`로 찍혀야 한다)
- [ ] 폴더 이름 변경과 폴더 삭제 → 안의 노트가 다른 기기에서도 옮겨지거나 휴지통으로 간다. (Obsidian이 폴더 안 파일마다 이벤트를 보내는지 `vault-event` 로그로 기록)
- [ ] macOS/iOS에서 `Note.md`와 `note.md`처럼 대소문자만 다른 이름 → 한쪽이 conflict 이름으로 바뀌고 덮어쓰기가 없다. (§9 대소문자 위험)
- [ ] macOS/iOS에서 `Note.md` → `note.md`처럼 대소문자만 바꾸는 이름 변경 → 다른 기기에도 그대로 반영되고 내용이 남는다.
- [ ] 노트 10개 이상을 한꺼번에 삭제 → 확인 창이 뜨고, "되살리기"와 "삭제 반영"이 각각 맞게 동작한다.
- [ ] 대량 삭제 확인 창을 Esc로 닫은 뒤 상태 표시줄 클릭 또는 명령 '삭제 확인 창 다시 열기'로 다시 열 수 있다.

## 3. 연결과 모바일
- [ ] 비행기 모드에서 편집 → 다시 연결하면 양쪽이 합쳐진다.
- [ ] iOS/Android에서 앱을 백그라운드로 보냈다 돌아온다 → 상태 표시줄이 곧 "동기화됨"으로 돌아온다.
- [ ] 잘못된 토큰 → "인증 실패" 상태가 되고 재시도하지 않는다. 올바른 토큰으로 바꾸고 "적용하고 다시 연결" → 정상 동작.
- [ ] 새 기기에서 잘못된 토큰으로 첫 동기화 → '인증 실패' 상태, 설정에서 토큰을 고치고 '적용하고 다시 연결'이 멈추지 않고 동작한다.
- [ ] 첫 동기화 중(오프라인) 플러그인을 끄거나 설정을 바꿔도 Obsidian이 멈추지 않고, 다시 켜면 정상 시작한다.
- [ ] '동기화 일시정지' 후 앱을 백그라운드에 보냈다 돌아와도 일시정지가 유지된다.
- [ ] 큰 볼트(노트 수천 개)를 iOS에서 처음 동기화 → 걸린 시간, 메모리, IndexedDB 사용량을 기록한다. (§9 모바일 용량 위험)

## 4. git 흐름
